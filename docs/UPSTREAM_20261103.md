## Validation design and limits

The existing CPU compiler/OpenMP matrix now includes all twelve affected
operator tests. On x86 these establish host integration, **not RISC-V kernel
execution**. Physical RISC-V/RVV/Zvfbfmin and Android NDK runtime compatibility
are not established by this test matrix.

A dedicated Apple Silicon job requires ARM64 and FP16 arithmetic, directly
executes the changed upstream pack8 kernel against an independent FP32
reference, and forbids unsupported-device skips. It must pass the pinned code,
fail numerically with the previous header (exit 2 and NUMERICAL_MISMATCH), then
pass again after restoring the exact pin. This controls for an ineffective
regression or an accidental fallback. It does not establish model performance.

The existing strict software-Vulkan tests, native four-platform builds, Qwen
0.5B CPU numerical/generation/tools/H5/history/fallback suite and installer
checks remain required. Use the exact PR/main commit's Actions evidence, not
old results, to evaluate the upgrade. The known Intel Mac full-installation
llm/image Vulkan probe exit=-6 is the owner's narrow standing exception;
no different failure is waived.
