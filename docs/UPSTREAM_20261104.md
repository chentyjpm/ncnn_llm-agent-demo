## Validation design and evidence boundaries

The existing compiler/OpenMP matrix retains upstream RMSNorm integration tests,
including the new upstream length/tail cases. A standalone direct-header test
checks changed x86 ISA paths against an independent double-precision reference,
with explicit CPU/OS feature checks and tested/unavailable reporting.

The physical Apple Silicon job retains mandatory FP16 depthwise coverage and
adds direct BF16 pooling execution, checking the two-column tail and adjacent
sizes against an independent FP32 max reference. BF16 storage is not a claim of
hardware BF16 arithmetic: this kernel only requires baseline AArch64 NEON.
The current header must pass, the prior header must fail numerically with exit
2 and NUMERICAL_MISMATCH, and the restored exact pin must pass again. Only the
generated companion object/executable are removed to force direct-header
recompilation; no source or user data is deleted.

The strict lavapipe test executes the actual PriorBox Vulkan layer, requires
FP16 support and submitted work, compares against independently computed
coordinates, and uses the same current/old/restored negative control. Software
Vulkan tests correctness, not physical GPU performance or model inference.

Existing native builds, real Qwen CPU tests and installer checks remain merge
gates. The owner's narrow existing Intel Mac full-installer llm/image probe
exit=-6 exception does not waive another failure and is not reported as a pass.
No Release is created. Unchanged image model generation is not claimed tested.
