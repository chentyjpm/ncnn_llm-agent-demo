## Source and interface review

- `455df56`: generic, x86 and Vulkan Reduction LogSumExp now subtract the
  reduction maximum before exponentiation, avoiding overflow/underflow for
  large finite inputs. Multi-axis collapse, channel padding and temporary
  workspace allocation change internally; public layer parameters do not.
- `f12423b`: adds ARM FP32 NEON CumulativeSum. Its vector-prefix scan and carry
  cover widths and scalar tails, dimensions 1–4 and positive/negative axes.
  The updated upstream test includes threading and boundary widths.
- `f6a0dc5`: clamps the exponential input to 10 for Vulkan Mish, including
  the shared scalar/vector fused-activation helpers. This prevents the
  infinity/infinity result in the expanded finite large-input test range.
- Eight later commits add RISC-V BF16 storage implementations for PReLU,
  BatchNorm, Bias, Scale, CELU, Eltwise, UnaryOp and BinaryOp, including vector
  conversion/dispatch helpers and a Scale FP16-storage path correction.

The existing ncnn build macros discover the new ARM/RISC-V files. No public
Net/Mat/Option signature, layer parameter schema, model format, tokenizer,
model-directory layout, application protocol or security-default change was
found. No application compatibility patch is indicated by source review;
actual compiler/link and inference compatibility remain test gates, not an
assumption. RISC-V hardware execution/performance is not established here.
The shifted LogSumExp code has no explicit positive-infinity guard: a +Inf
input can produce Inf-minus-Inf/NaN where the old generic scalar path gave
+Inf. This finite-input upgrade does not claim IEEE special-value equivalence
or correctness for arbitrary Inf/NaN model inputs. No such product path has
been established; real supported-model inference remains mandatory.

## Validation and boundaries

The upgrade extends existing CPU coverage with upstream Reduction and
CumulativeSum tests and an independent double-reference LogSumExp companion.
Strict software-Vulkan checks cover large finite Reduction, standalone Mish
and fused depthwise Mish, including vector lanes. Old CPU/Vulkan Reduction
negative controls must fail numerically, not merely fail to build or lack a
Vulkan device. Old Mish is a diagnostic: drivers which already return
tanh(Inf)=1 may not reproduce that old failure, which is explicitly reported
rather than treated as a new-kernel failure or proven negative control.
Current sources are restored and rerun after either diagnostic. The ARM job
adds the upstream CumulativeSum axes, threading and tail suite on physical
Apple Silicon. Existing focused regressions remain enabled.

Retain four-platform native compilation, real official Qwen CPU inference
and complete installer tests. Download jobs retain their resource prechecks.
Do not rerun the unrelated large SDU/model matrix. Software Vulkan is not
physical GPU performance evidence. Package smokes are not model inference;
unchanged image-engine packaging is not a fresh image-generation benchmark.
